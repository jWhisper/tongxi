# 第一期需求：本地 Agent 协作 MVP

迭代：001-mvp-20260927。创建日期：2026-09-27。

本文件保存本期的需求和范围基线；执行情况见 [进度记录](progress.md)，分阶段交付与验收见 [实施计划](implementation-plan.md)。长期设计见 [技术架构](../architecture.md)。

## 1. 背景与使用场景

同席是一个本地运行的通用 Agent 协作软件。用户可以创建不同角色的 AI 伙伴，与它们交流，也可以让它们互相发消息、分工协作，并查看整个过程。

产品不限定于编程。首批验证场景采用资料整理、写作与评审等通用任务；编程可以成为后续支持的一种用途。

典型例子：用户让「写作助手」起草活动介绍，写作助手联系「评审助手」检查表达，再根据反馈整理最终内容。人和 Agent 的公开交流都能在同一个会话中看到。

## 2. 已确认的方向

- 项目名称：同席 / Tongxi。
- 产品本地运行，优先满足个人使用。
- 支持创建 Agent，以及 Agent 之间交流。
- 一期同时覆盖「主要助手带着伙伴做事」和「用户与多个 Agent 讨论」的基础体验，共用消息和执行机制。
- 用途通用，不以代码仓库、终端或 Git 为产品中心。
- Go 作为后端语言，Eino 作为 Agent 执行框架。
- 当前阶段先完成规划，随后按阶段实施。

## 3. 本期默认方案

以下是为推进首版而明确列出的设计默认值，后续调整时应同步修改相关文档：

| 项目 | 默认方案 |
| --- | --- |
| 桌面界面 | Wails v2 + React + TypeScript + Vite |
| Agent 执行 | Eino ADK 的 ChatModelAgent + Runner |
| 本地存储 | SQLite；角色、会话、消息、执行记录保存在本机 |
| 模型来源 | OpenAI 兼容 Chat Completions 接口；P0 首个实测服务为 Kimi Code，Base URL 为 https://api.kimi.com/coding/v1，模型为 kimi-for-coding；密钥仅在本机配置 |
| 通信方式 | 本地服务路由消息，数据库保存待执行记录，内存信号唤醒调度器 |
| 运行形态 | 一个桌面应用中的 Go 服务，不为每个角色常驻一个进程 |
| 首个验证平台 | macOS；跨平台打包待核心功能稳定后验证 |

「本地运行」指应用和业务数据在本机，不代表模型推理完全离线。使用模型 API 时，相应的输入内容会发送给该模型服务。具体服务商、模型、Go 版本和依赖版本在 P0 阶段确定并锁定。

## 4. 本期范围

### 必须交付

1. 创建、编辑、停用 Agent：名称、简介、角色指令、模型配置和可用工具。
2. 与单个 Agent 私聊，支持流式回复和历史记录。
3. 创建包含多个 Agent 的简单会话，支持助手带队与多人讨论；主要助手按会话指定。
4. Agent 能列出同会话中的伙伴，并向指定伙伴发送消息。
5. 显示谁在等待、谁在运行、谁失败，以及消息由谁发送。
6. 停止一次自动协作，限制自动执行次数。
7. 应用重启后保留配置和历史；中断与失败状态可见。
8. 带队模式默认由主要助手接收请求、联系伙伴并整合结果；讨论模式支持点名、大家说一轮和指定成员总结。

普通公开消息不会自动唤醒所有成员。用户明确选择「大家说一轮」时，一条提问安排多个成员按顺序各回复一次，后发言者可读取先前发言；该轮不允许 Agent 自行追加执行。点名和指定总结只运行指定成员一次。

带队模式允许消息工具继续交接；讨论模式由用户控制下一轮。模式切换仅在当前会话无待执行或运行中任务时进行，历史保留。轮流讨论失败或中断后结束本轮并取消后续安排，用户可重新发起；人数超出执行预算时在开始前提示。

P0 先交付连接验证工作区，不提前实现群聊与角色管理；缺少真实模型配置时可完成本地集成验证，但不能将真模型验收标为通过。

### 后续按需求增加

- AgentAsTool 子任务委派：首个场景为「主要助手调用评审 Agent，再根据返回意见继续修改」。复用角色配置、独立子任务上下文，关联父执行并继承停止与预算；一期先完成消息协作，不混用两种调度机制。
- 自动主持、多轮自动讨论、并行派活汇总、固定工作流程。
- 搜索、文件处理等实际工作工具，随后再考虑 MCP 和 Skills。
- 长会话总结、跨会话记忆与知识库。
- 接入现成 Agent 运行时，例如 Hermes 或其他支持程序化调用的 Agent。
- 本地模型、Windows/Linux 打包、任务看板和定时任务。

### 首版不做

- 多用户组织、跨机器协同和云同步。
- 独立 Relay、Nostr、联邦通信或公私钥成员体系。
- Redis、外部消息队列、Postgres、微服务拆分。
- Git 托管、内置 IDE、自动代码合并。
- 通用插件市场、可视化工作流编辑器、自主创建 Agent。

## 5. 整体验收标准

用户能在界面创建「写作助手 A」和「评审助手 B」，把它们加入同一会话；A 通过工具给 B 发消息，B 回复并可联系 A；用户能看到有署名的全过程，随时停止，重启应用后历史仍在。

另验证多人讨论：一条用户问题只显示一次，选定成员依次各回复一次，后发言者能看到前文；该轮完成即停止，用户可以指定一位成员总结。两种模式共享角色和聊天界面，切换不会丢失记录。

自动化验证应使用可控的假模型验证消息路由、顺序、停止和次数限制；真实模型验证用于确认所选模型的流式输出与工具调用确实可用，不能只依赖假模型判定可发布。
