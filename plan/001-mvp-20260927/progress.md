## 0.1.1 自动协作体验修正（2026-09-27）

用户反馈「交给主要助手」仍需手动 @ 和选择多种发言方式。原实现只提示模型“需要时联系”，成员完成后也没有调度层自动返回主要助手的保证；此前带工具指令的验收未覆盖普通任务的默认体验。

- 群聊移除发言模式、手动选人和指定总结入口，只保留「发送」；会话设置只选择成员和主要助手。旧版 discussion 会话无需重建，没有主要助手时取第一位启用成员。
- 主要助手直接获得当前成员名单、准确 ID、职责和启用状态；方案/创作/分析任务要求主动用 send_message 分工。受邀成员也具备联系其他成员的能力，普通公开回复自动交回主要助手。
- 最后一个受邀成员完成时，在保存回复的同一事务中排队主要助手总结，保留原问题和公开意见。6 次额度最后一次留给总结，最终总结不再追加成员；停止、失败、停用与重试维持同一链约束。
- 自动化验证：`make test`、`go test -race ./internal/...`、`go vet ./...` 通过；新增多成员完成后唯一总结、重启保留总结任务、停用主要助手、停止后迟到完成、成员/总结重试与额度回归。
- 原生 Kimi 验收：创建「自动协作验收 0.1.1」，只发送“面向新邻居、预算有限、15 人、90 分钟读书会”的普通需求，没有 @、工具名或指定发言流程。写作助手自主投递给策划和评审，二者分别公开发言；随后系统自动唤回写作助手给出流程、邀请文案、待确认项和关键取舍。4 个 Run 全部 completed，Chain completed，最终正文 1069 字符；2 次 send_message 均为真实工具调用。

## P2 实际交付与验收

- [队列与历史存储](../../internal/store/queue.go)：版本 3 扩充 runs，保存输出、时间、revision、角色配置快照与 transcript，并增加独立 deliveries 投递表。用户消息与初始 Run、最终公开回复与完成状态分别原子提交；重复投递返回原 Run，一条消息仍允许关联多个 Run。

- [执行层](../../internal/agent/runner.go)：按角色 instruction 与 tools 构建 ChatModelAgent，通过 Runner 消费流式事件；保存完整消息，包括 reasoning_content、tool_calls 与 tool_call_id。失败/取消轮次不回放到下一轮。
