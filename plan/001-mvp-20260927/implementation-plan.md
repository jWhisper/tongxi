# 第一期实施计划：本地 Agent 协作 MVP

创建日期：2026-09-27。

范围基线见 [本期需求](requirements.md)，阶段状态与实际验证结果见 [进度记录](progress.md)。本文件保留分阶段工作清单和验收标准；执行时同时维护工作清单与进度记录。

按 P0 → P1 → P2 → P3 → P4 顺序推进。每一阶段都要得到可以演示的结果；验收未通过时，先修复本阶段问题。暂不承诺工期，P0 验证后再依据实际工作量估算。

## P0：验证技术链路并锁定版本

目标：确认 Wails、Eino、所选模型和本机环境能完成最小交互。

工作：

- [x] 初始化 Wails v2 + React/TypeScript 工程，确认开发和打包流程。
- [x] 选择一个实际可用的模型服务，验证普通回答、流式输出和工具调用。
- [x] 用 Eino ChatModelAgent + Runner 接入一个确定性示例工具，验证事件消费。
- [x] 验证取消请求、流关闭和超时在选定 Eino/模型适配器组合中的行为。
- [x] 确认该版本的消息类型、工具构造方法和 Eino 扩展组件兼容性；示例代码以锁定版本为准。
- [x] 验证 SQLite 驱动与桌面打包、应用数据目录、系统凭据存储的可用性。
- [x] 把验证通过的 Go、Wails、Eino、模型组件和前端依赖版本锁定到工程中。

验收：

1. 本地桌面窗口能调用 Go 方法并展示连续文本事件。
2. 真模型能调用示例工具，并在拿到结果后结束一次 Agent 执行。
3. 点击停止后 UI 能结束等待；后端执行可取消或在已设超时内结束，流资源被释放。
4. 记录实际验证的模型、平台和版本；验证凭据不进入仓库或日志。

P0 已通过验收：本地固定模型、临时兼容接口服务、自动化测试与构建通过，并已补齐 Kimi Code `kimi-for-coding` 的真实回答、流式工具调用、取消，以及原生窗口发送、停止和重启保留验证记录。具体证据见 [进度记录](progress.md)。

交付：最小运行工程、依赖锁定、简短验证记录。此阶段不构建多 Agent 功能。

## P1：应用基础、持久化和 Agent 管理

依赖：P0。

目标：用户能创建持久化角色，并进入对应会话。

工作：

- [x] 建立本地数据库迁移和独立开发/测试数据目录。
- [x] 实现 Agent 创建、编辑、停用和列表。
- [x] 保存角色名称、简介、指令、模型配置及工具选择。
- [x] 后端管理模型凭据，数据库只存密钥引用。
- [x] 实现私聊、多人成员配置及会话列表；保存协作方式和主要助手，校验其成员身份。
- [x] 建立公开消息与运行记录的基本读写，消息有稳定 ID 和发送者。
- [x] 实现 Wails 业务调用及业务事件，前端可在重新打开会话后从数据库刷新。

验收：

1. 创建两个角色并重启应用，两者的配置和会话仍然存在。
2. 编辑一个角色不会改动另一个角色；停用后不接受新执行，历史署名仍可辨认。
3. 同名显示不会影响 ID 路由；会话成员关系可以准确读取。
4. 界面错误能区分配置缺失、存储失败等原因，输入内容不会无提示丢失。

交付：可操作的 Agent 管理和会话界面，持久化基础。

## P2：单 Agent 对话闭环

依赖：P1。

目标：完成「发送 → 排队 → Eino 执行 → 流式展示 → 保存结果 → 继续对话」。

工作：

- [x] 从角色配置构建 Eino ChatModelAgent，并通过 Runner 执行。
- [x] 保存模型 transcript，包含工具调用和结果，按 Agent + 会话隔离。
- [x] 实现单执行槽调度器，queued Run 作为持久化待办。
- [x] 同一事务提交触发消息和待执行记录；最终回复与完成状态原子提交。
- [x] 实现运行状态、超时、错误和单次执行取消。
- [x] 完成有限上下文窗口，保留完整工具调用/结果组合。
- [x] 执行开始固定配置快照，避免配置修改影响当前轮次。

验收：

1. 连续两轮交流能引用前文；重启应用后继续对话仍可读取所需历史。
2. 两个会话交替聊天，角色和历史不串线。
3. 单 Agent 对话中运行期间新消息可以排队，同一投递重送不会重复创建初始 Run；数据模型允许以后由一条消息安排多个成员执行。
4. 假模型模拟流式完成、模型报错和取消，数据库状态与界面一致。
5. 至少一个真实模型完整跑通两轮对话和示例工具调用。

交付：单 Agent 可用版本，不以多角色配置数量代替多 Agent 通信能力。

## P3：带队协作与多人讨论

依赖：P2。

目标：先完成主要助手通过消息联系伙伴，再完成用户控制的多人讨论，共用角色、消息、运行状态与停止机制。

工作：

- [x] 实现 list_agents 和 send_message 两个工具。
- [x] UI 接收者选择绑定 Agent ID；支持默认主要助手、点名、大家说一轮和指定总结，普通发布不广播触发。
- [x] 服务端绑定发送者、会话和 Chain，检查接收者及回复关系。
- [x] 实现 Chain 计数、最多 6 次 Agent 执行和事务内额度预留。
- [x] 实现用户请求和工具投递幂等，避免同一请求重送产生重复消息。
- [x] 将接收者的待执行记录异步排队；发送工具不等待接收者执行完成。
- [x] Agent 按自身游标获取同会话新增公开内容，其他成员的私有工具记录不共享。
- [x] 会话内显示投递、等待、执行和最终回复的对应关系。
- [x] 集中实现发言安排函数；同一消息允许关联多个 Run，保存本次模式与有序参与者快照。
- [x] 实现固定顺序的一轮讨论：事务内创建完整安排和预留额度，按前置执行成功条件推进，每人一次。
- [x] 讨论点名、轮流发言和总结时不开放可新增执行的 send_message；失败/中断取消后续安排。
- [x] 无在途任务时允许修改会话模式/主要助手，不改变已有 Chain 快照。

验收：

1. 假模型驱动 A → B → A，三次执行身份、消息顺序和上下文归属正确。
2. send_message 先返回排队确认，A 结束后 B 可以运行，不发生相互等待。
3. 一条普通群消息或最终回复不会触发所有 Agent 自动发言。
4. 接收者不存在、被停用或不在会话中时，不创建新待办。
5. 同一 client_request_id 或同一工具调用重复提交，只产生一条投递及其待办。
6. A、B 持续互发时，最多创建 6 个属于该 Chain 的 Run，并清楚显示达到上限。
7. 真模型演示「写作助手请评审助手检查一段活动文案」；合作通过消息工具实际发生，而非在文字中声称已经联系。

8. 三成员讨论只显示一条提问，三位按顺序各回复一次；后者获得前者公开消息，完成后无额外 Run，指定总结只执行一次。
9. 讨论人数超额或成员无效时整组不入队；重送操作不重复安排，某位失败后不继续执行其后成员。
10. 切换模式不改变已有记录；运行中禁止切换。

交付：带队协作与用户控制的多人讨论均可演示。

## P4：停止、启动恢复和首版发布验证

依赖：P3。

目标：保证用户可以终止自动协作，应用退出后状态可解释，并交付本地安装包。

工作：

- [x] 实现 Chain 级停止：禁止新增任务、取消 queued、请求取消 running。
- [x] 处理停止与消息投递并发、晚到模型事件和工具返回。
- [x] 退出时停止新任务认领；启动时将残留 running 标为 interrupted。
- [x] 扫描有效 queued 待办；失败或中断 Run 只在用户明确重试后重新执行。
- [x] 带队重试保留原 Run 及消息，关联原 Run，并计入原 Chain 剩余额度；讨论中断后重新发起新一轮，不自动重放后续安排。
- [x] 停用角色时取消其尚未执行的待办，并停止其正在执行的 Run；重新启用不自动重放旧任务。
- [x] 验证启动恢复不把 stopped Chain 的任务重新执行。
- [x] 输出首个 macOS 安装包和使用说明，记录尚未验证的平台。

验收：

1. A 正在处理、B 已排队时停止，A 进入取消处理，B 不再执行，该 Chain 不产生后续 Run。
2. 停止和 send_message 同时发生时，事务顺序决定结果；已提交消息保留，停止后不得继续执行链内新任务。
3. 入队提交后、发出唤醒信号前退出，重启仍能发现待办。
4. 模型执行期间强制退出，重启显示 interrupted，不能自动再次调用模型冒充恢复成功。
5. 晚到的完成事件不能覆盖 cancelled/interrupted 状态，部分文本不会显示成成功结果。
6. 安装包在目标 macOS 环境可启动；创建两个角色、交流、停止和重启保留历史的完整链路通过。

交付：MVP 安装包、运行说明、已知限制和首版验收记录。

## 验证方式

| 层次 | 主要验证内容 | 方法 |
| --- | --- | --- |
| 存储 | 事务、幂等、游标、迁移、启动恢复 | 使用临时 SQLite 数据库 |
| 调度 | 顺序、停止、次数限制、重试和晚到事件 | 可控假执行器/假模型，不依赖随机回复 |
| Eino 接入 | 工具调用与结果配对、流关闭、取消与错误转换 | 锁定版本的集成验证 |
| 产品链路 | 创建角色、选择接收者、展示署名、停止和历史 | 桌面交互验证 + 真实模型冒烟 |

测试服务于状态与行为约束，避免为简单字段映射或纯样式修改编写镜像测试。每个阶段记录实际检查结果，不把“有测试文件”视为通过。

## MVP 之后的候选方向

只在真实使用场景提出需求后选择实施，不构成首版承诺：

1. 增加搜索、文档处理等工作工具，形成具体任务闭环。
2. 首个 AgentAsTool 增强为评审子任务：验证返回结果后继续、独立上下文、父子记录、取消和预算传播；不进入被父任务占用的同一队列等待。
3. 按需要增加有限并行、自动主持、长历史总结和人工确认中断。
4. 接入 MCP/Skills 或现成 Agent 运行时。
5. 根据使用频率决定任务看板、定时工作和其他平台支持。

P0–P4 已完成，本期本地 MVP 已交付。后续按实际使用反馈立项；AgentAsTool 是首个增强候选，不自动进入插件系统或通用工作流平台开发。
