# Token 预算、持久摘要与历史回查

状态：0.1.17 已实现并完成验收。范围为本阶段用户明确要求的三点，不修改群聊组织策略。结果见 [进度](progress.md)。

## 实现顺序与验收

1. 取消加载历史时的 12 轮/50 条/字符截断。冻结输入范围，只有成功处理原文或摘要后才提交成员位置；超过 100 条消息、失败和取消均不能漏读。
2. 每次模型请求计算全部输入（系统指令、任务状态、工具定义、历史、工具结果），保留输出和安全余量。模型设置增加可选上下文容量；未知模型用保守默认值。服务商 prompt_tokens 校准估算，不能由用量反推出容量。
3. Eino reduction 先缩减工具结果，完整结果存应用 SQLite；Eino summarization 按预算分批摘要旧讨论，不能把已经超限的输入再交给摘要模型。当前任务/验收/成果与最新用户请求保持原文。
4. SQLite 按会话、角色、执行类型保存压缩后的上下文和覆盖位置，与成功执行一起提交；原始记录保留。下次只追加未覆盖的已完成执行，重启后不重新加载已覆盖原文。失败保留上次有效状态。
5. search_chat_history 按关键词查本会话公开消息；read_chat_history 按消息 ID/序号分页回查及相邻消息。工具结果转存另有仅本角色可读的工具。工作目录不生成 history 目录。

## 验收场景

- 长群聊、单条长消息和超过 12 轮历史均无未覆盖空洞。
- 预算从 800 改为 200，压缩后任务状态和最新要求仍为 200；可回查早期拒绝场地的原始依据。
- 工具定义、大段工具输出和中文内容均计入预算；连续工具调用也压缩。
- 摘要失败、取消、保存失败不提交新上下文或已读位置；工具调用/结果成对保留。
- 重启复用已保存摘要；不同会话、角色以及 selector/reply 私有上下文隔离。
- 历史查询分页可继续读取长消息，支持中文，原文内容视为资料而非新指令。
- Go 回归测试、前端类型检查与测试；模型设置在原生窗口与窄窗口检查。

## 取舍

Token 是保守估算而非所有厂商都精确可用的 tokenizer；以实际 prompt_tokens 持续校准。摘要有损，任务表为当前事实来源，原始消息供回查。容量不够容纳当前任务与工具定义时明确失败，不静默丢弃当前要求。未上线，直接更新当前结构，不增加旧数据迁移链；运行新版本前需备份并重建旧开发数据库，原始工作文件保留。
