# 同席（Tongxi）规划与迭代索引

> 同席 — 让你的 AI 伙伴一起交流、一起做事。

更新日期：2026-09-29。

同席是本地运行的通用 Agent 协作软件，支持创建角色、交流与分工。产品用途不限于编程，可以覆盖资料整理、写作、评审等场景。

## 当前开发原则

项目尚未上线，后续修改直接面向当前设计，不以兼容旧数据为目标。优先简洁清楚的代码和好看、好用的界面；具体约定见 [AGENTS.md](../AGENTS.md)。旧迭代中已记录的迁移与兼容行为保留为历史事实，不再约束后续实现。

## 新增迭代的约定

1. 每期目录直接放在 `plan/` 下，采用 `NNN-topic-YYYYMMDD`：三位顺序编号、简短英文主题、创建日期，例如 `001-mvp-20260927`。
2. 日期表示迭代立项日期；更新和完成时保留原目录名，避免历史链接失效。
3. 每期建立 README、requirements、implementation-plan、progress 四份文档，并在本页登记。
4. 需求先写清目标、范围、默认假设和验收标准，再拆分实施阶段。
5. 只有改变当前系统设计时才更新外层 architecture；新增参考来源时才更新 references。

## 跟进方式

| 文档 | 回答的问题 | 何时更新 |
| --- | --- | --- |
| `requirements.md` | 本期要交付什么，哪些内容不在本期？ | 需求确认或范围变化时 |
| `implementation-plan.md` | 分几步做，每一步怎样验收？ | 拆分阶段、调整步骤或完成清单项时 |
| `progress.md` | 现在做到哪，证据是什么，下一步是什么？ | 完成实质工作、发现阻塞或作出决策时 |

阶段状态与执行证据以各期 progress 为准，本页和本期 README 不再复制进度百分比或阶段状态表。细粒度工作项在 implementation-plan 勾选，实际结果和相关链接记在 progress。

进度状态统一使用：`未开始`、`进行中`、`阻塞`、`已完成`、`已取消`。阻塞必须写明原因和解除条件；完成必须关联验收结果，不能只以代码存在或文档写完作为依据。

一期完成时，在 progress 记录交付物、验证结果、遗留事项及其去向，保留本期最终需求与计划。后续新增能力在新一期提出，避免把历史目标改写成新目标。

小改动直接记录在该期的变更记录中；只有明显复杂的专项方案才新增独立文档，不提前创建空目录和多套模板。
