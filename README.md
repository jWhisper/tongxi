# 同席 · Tongxi

让你的 AI 伙伴一起交流、一起做事。

本地桌面 Agent 协作软件，群聊支持主要助手带队和自由讨论。后端使用 Go + Eino ADK，界面使用 Wails v2 + React/TypeScript，数据存储在 SQLite。

## 当前实现

当前已完成 **P0–P4 本地 MVP（0.1.2，含自由讨论）**，包含：

- 创建、编辑、停用和重新启用角色；分别保存名称、简介、指令、模型连接及工具选择。
- 新建私聊与多人会话，配置成员与群聊方式；带队模式指定主要助手。
- 私聊发送后进入持久化队列，角色按配置调用 Kimi，流式回复并保存结果；执行期间可继续发消息。
- 已收到的文本按动画帧平滑显示，密集事件合并刷新；完成或停止时立即对齐准确内容，历史消息直接显示。
- 对话历史按角色与会话隔离，保留完整工具调用和结果，支持重启续聊。
- 显示排队、执行、完成、失败、中断与取消；可停止当前回复，私聊可单独取消排队；群聊停止会取消本次所有执行中和排队任务，失败会取消后续安排。执行超时为 90 秒。
- 群聊直接发送即可；带队模式的主要助手默认获得成员名单和协作工具，按职责自动 @ 伙伴，不要求用户编写工具指令。
- 带队模式在所有已邀请成员完成后，自动安排主要助手根据原问题与公开意见汇总结论。每次协作最多执行 6 次，最后一次留给总结；成员也可邀请其他伙伴补充。
- 自由讨论按话题动态选人，成员可以接话、邀请伙伴或保持沉默；没有新内容时暂停，不强制总结。每轮最多 6 次发言机会和 6 次后台选人，用户新消息会打断旧讨论。
- 展示发送者、接收者、回复引用、等待关系和协作进度；前序失败或中断时取消后续安排。
- 带队/私聊失败或中断可手动重试，关联原任务、不重复原消息，并计入同一协作的剩余额度；已停止的协作不续跑。可通过「重新发起」填入原问题，发送一次新协作。
- 停用角色会停止涉及它的在途协作；重新启用不重放旧任务。
- 页面或会话切换保留未发布草稿，保存失败保留表单；草稿不跨应用重启保存。

同时保留 P0 连接验证工作区：

- OpenAI 兼容 Chat Completions 接口配置；Base URL、模型名称与 API Key 在本地设置。
- 系统凭据存储保存 API Key；SQLite 只保存引用及非敏感配置。
- 单次 Eino 执行、流式显示、确定性字符统计工具、停止和 90 秒超时。
- 不联网的固定测试模型，用于检查 Eino 工具调用与界面事件链路；它不是实际 LLM。
- 验证结果保存在本机，界面显示最近 30 次；重启后未完成执行标记为中断，不自动重试。

私聊已使用 Kimi Code 的 `kimi-for-coding` 跑通真实多轮对话、工具调用和停止。群聊已实测写作 → 评审 → 写作、三位成员依次讨论及指定总结；0.1.1 将群聊入口收敛为「发送」，0.1.2 增加无需固定主持人的自由讨论，历史会话无需重建。已支持整次协作停止、带队/私聊显式重试、停用角色时清理在途任务及启动恢复。验收范围见 [第一期进度](plan/001-mvp-20260927/progress.md)与[自由讨论进度](plan/002-free-discussion-20260927/progress.md)。

## 两种群聊方式有什么区别

两种模式都能自动发言、互相 @，用户都只需发送消息。主要助手带队强调分工后交付结果；自由讨论强调围绕观点继续交流，允许保留分歧和未决问题。

两种模式的所有成员都能读取同一群聊内其他成员已发布的回答及其署名，公开 @ 消息也不只对接收者可见。上下文在每次开始发言时加载，不实时读取别人尚未完成的流式片段；其他会话和其他成员的私有工具记录不共享。模型只读取有限历史窗口，不能把聊天记录已保存理解为每次都完整记住全部历史。

| 对比 | 主要助手带队 | 自由讨论 |
| --- | --- | --- |
| 谁组织 | 指定主要助手理解任务、分配具体工作，伙伴也可继续邀请其他成员 | 无固定主持人；后台按最近发言和成员职责选人，成员也可邀请伙伴回应 |
| 怎样发言 | 主要助手分工，受邀成员完成分配的任务 | 接着前面的观点补充、质疑或回应，没有新内容可以跳过 |
| 怎样结束 | 已邀请成员成功完成后，自动交回主要助手汇总结论、分歧和下一步 | 没有新内容或达到上限时暂停；不自动安排总结，需要时用户直接提出 |
| 适合什么 | 目标明确，希望拿到完整方案、修改稿或建议 | 头脑风暴、探索需求、比较想法，希望先听不同观点 |

例如，同样讨论社区读书会：带队模式会分配策划和评审任务，最后由主要助手整理活动方案；自由讨论可能从破冰方式聊到内向者的参与压力，成员沿着具体观点修正建议，暂时没有补充就停下来。发言顺序由当时内容决定，不固定轮流。

当前两种模式共用串行执行和消息工具，所以界面看起来相似。自由讨论仍有后台选人调度：它只决定下一位发言者或是否暂停，不以成员身份发言、不分配子任务，也不承担最后汇总的职责。当前并不是所有 Agent 同时监听并自主抢话；讨论暂停也不表示已经达成共识。

具体行为与验收边界见 [自由讨论需求](plan/002-free-discussion-20260927/requirements.md)。

## 本地开发

本次验证环境为 macOS arm64、Go 1.25.8、Node.js 26.9.0、npm 11.19.1，以及 Xcode Command Line Tools。Go 工具链声明、`.node-version`、`go.sum` 和前端锁文件共同记录版本。其他系统尚未验证。

在仓库根目录执行：

```sh
make setup
make dev
```

`make setup` 下载依赖，并把固定版本 Wails CLI 安装到项目的 `.tools/`；不会替换全局 Wails。`make dev` 启动桌面窗口和前端开发服务，默认使用仓库内 `.local/dev` 的独立数据库；可用 `TONGXI_DATA_DIR` 覆盖。开发目录初始为空，需要单独配置连接；已构建桌面包仍读取系统应用数据目录中的既有 Kimi 配置。

如果停在 `Installing frontend dependencies:`，表示 Wails 正在执行 npm 安装，默认不会实时展示下载日志。首次安装或网络重试可能较慢；这一步与模型配置无关。安装现在优先使用 npm 缓存，缓存缺失时仍会下载锁文件中的版本。

如需查看下载过程，在运行 `make dev` 的终端按 `Ctrl+C` 停止后，依次执行：

```sh
cd frontend
npm ci --prefer-offline --no-audit --no-fund --loglevel=verbose
cd ..
make dev
```

启动成功后会出现 Vite 的 `Local` 地址、Wails 的开发服务信息和同席桌面窗口。保留终端运行；`Ctrl+C` 会结束开发模式。

只运行 `frontend` 下的 `npm run dev` 是界面预览，不具备 Go 绑定；界面会明确提示，不能在该预览中执行模型或保存配置。

## 验证与打包

角色与会话管理验收：

1. 在「模型设置」配置默认连接，在「角色」创建写作助手与评审助手，填写不同指令。同一地址可留空密钥，沿用默认连接；每位角色的连接配置独立保存。
2. 编辑其中一位，确认另一位不变；停用角色后不可新建该角色的私聊，已有会话仍保留成员身份。
3. 从角色卡片新建私聊；在「会话」新建多人会话，选择至少两位启用角色和群聊方式。带队模式的主要助手必须属于所选成员，自由讨论不指定主要助手。
4. 发布一条消息，切换会话再返回，确认历史与署名；退出并重启后，角色、会话、消息和停用状态仍在。
5. 输入草稿后切换页面或会话，确认草稿仍在；尝试只选一位成员保存多人会话，确认报错且输入保留。

自动协作验收（0.1.2）：

1. 打开带队模式群聊，直接发送一个需要方案、创作或分析的问题，不写 @、工具名或指定发言流程。
2. 主要助手应自动调用消息工具分工，界面出现具名投递；受邀伙伴随后发言。
3. 全部受邀伙伴完成后，主要助手自动给出最终结论，无需点击额外按钮；中途停止后不能继续唤起总结。
4. 历史会话保持原有模式；带队模式没有主要助手时自动选用第一位启用成员，自由讨论不使用这个兜底。
5. 排队或执行期间不能修改会话设置；停用主要助手会停止相关协作。

自由讨论验收（0.1.2）：

1. 会话设置选择自由讨论，不指定主要助手，直接发送普通问题。
2. 成员按话题接话，可以跳过；后台选择和沉默不作为聊天消息。
3. 发送新话题会停止本会话旧讨论；停止后的迟到内容不能继续投递。
4. 没有新内容或达到预算时暂停，不强制总结；需要总结可直接询问。
5. 每轮最多 6 次发言机会和 6 次后台选人，选人使用独立提示词与公开上下文。

详细进度见 [自由讨论迭代](plan/002-free-discussion-20260927/progress.md)。

P2 私聊验收：

1. 打开角色私聊，告诉它一个活动代号；要求实际调用 `count_characters` 统计一段文本。确认界面出现工具调用记录，而非仅在回答中声称调用。
2. 继续询问代号和工具结果，退出并重启后再次询问；应能引用已完成轮次的历史。
3. 发送较长请求，生成期间再发送一条消息；第二条显示排队。可单独取消排队，或在输入区点击「停止当前回复」。取消的部分内容保留为未完成，不作为正式回复加入下一轮模型上下文。
4. 打开另一条私聊发送不同内容，确认历史不串线。一次只有一个执行槽，其他会话的消息也按入队顺序等待；连接验证与角色执行不并发。

P0 检查仍可在「连接验证」执行，无需配置模型：

1. 顶部出现「本地已就绪」，选择「本地检查」，点击「运行检查」。预期显示「已调用字符统计工具」、逐步输出字符数为 2 的回复，最终状态为「已完成」。
2. 再运行一次，在回复输出时点击「停止」。预期状态变为「已停止」，之后不再追加文字。
3. 退出应用并结束 `make dev`，重新执行 `make dev`。预期之前的验证记录及状态仍在。

这三步验证桌面、Eino 工具调用、取消和本地保存。真实模型验证可以等配置准备好后再做，步骤见下方。

```sh
make test
go test -race ./internal/...
make probe
make build
```

`make probe` 默认执行离线固定测试。桌面开发包位于 `build/bin/tongxi.app`。

## macOS 安装包

运行 `make release` 生成 `build/bin/Tongxi-0.1.2-macos-arm64.dmg` 及 SHA-256 校验文件。打包脚本重新构建应用，收集本机锁定依赖的许可证，进行 ad-hoc 签名与验证，生成并校验只读 DMG；镜像包含应用、Applications 快捷入口与使用说明，不包含用户数据库和密钥。

安装和操作说明见 [INSTALL.md](INSTALL.md)。已在 Apple Silicon、macOS 26.6.2 验收；其他系统未验证。此包未做 Developer ID 签名或公证，不能将本机验收等同于其他电脑无提示安装。

系统凭据存储的集成测试需显式启用，只写入临时无敏感内容的条目并清理：

```sh
TONGXI_TEST_KEYRING=1 go test ./internal/app -run TestSystemVaultRoundTrip -v
```

真实模型有两种验证方式：

1. 桌面「模型设置」填写 Base URL、模型名和 API Key，保存后切到「真实模型」，使用工具验证示例并发送；确认界面实际出现工具调用。填写地址应为 API 根路径，通常以 `/v1` 结尾。
2. 在受控的本地 shell 中设置 `TONGXI_BASE_URL`、`TONGXI_MODEL`、`TONGXI_API_KEY` 后运行 `go run ./cmd/probe -live`。不要把真实密钥写入源码、提交记录或共享命令。

普通文本回复成功不等于工具调用验证成功；真实服务必须实际支持流式工具调用。每次 P0 验证互相独立，暂不带入上一条验证的上下文。

本次验证的 Kimi 连接（2026-09-27）：

- Base URL：`https://api.kimi.com/coding/v1`。
- 模型 ID：`kimi-for-coding`；通过该账号的 `/models` 接口确认可用。
- API Key：仅保存在本机系统凭据存储中，仓库不提供密钥；在另一台机器使用时需自行配置。

Kimi Code 会员 API 与开放平台 API 使用不同的密钥和地址。开放平台地址为 `https://api.moonshot.cn/v1`，需要该平台的密钥及模型 ID；不能直接沿用上面的会员配置。此次验证仅覆盖个人本机的 Kimi Code 接口，后续产品集成按实际用途选择服务。参见 [Kimi 官方接口说明](https://www.kimi.com/code/docs/)。

## 数据与凭据

默认数据目录是系统用户配置目录下的 `tongxi`，macOS 对应 `~/Library/Application Support/tongxi`。开发/测试可通过 `TONGXI_DATA_DIR` 指向独立目录。不要并行启动多个实例使用同一数据库。

数据库文件为 `tongxi.db`。版本 2 增加角色、会话、有序成员、公开消息与运行记录；版本 3 扩充 `runs`，保存配置快照、输出、状态、revision 与模型 transcript，并增加 `deliveries` 记录用户投递幂等。版本 4 增加 `chains`、`tool_deliveries`、`member_cursors`，扩充投递、执行依赖、输入快照和消息对应关系；版本 5 增加 `retry_of`、重试请求幂等以及会话配置版本；版本 6 增加后台选择 Run 类型和沉默标记。旧配置及已有历史在迁移后保留。

消息与初始任务在同一事务提交，最终公开回复与 completed 状态在同一事务提交。同一发送标识重送不会重复创建消息或初始任务；不同标识允许发送相同文本，一条消息可关联本轮多个 Run。群聊在事务中校验所有成员、预留最多 6 次执行额度并完整入队；同一工具调用重送也不重复投递。

每次执行开始固定角色配置与凭据，修改角色只影响下一次执行。模型上下文只读取该角色、该会话最近最多 12 个已完成轮次，总计不超过 48,000 个序列化字符，再追加当前消息；按完整轮次截断，不拆散工具调用和结果。完整记录仍在数据库中，失败/取消的轮次不参与续聊。P1 只发布、未执行的消息不作为私聊模型历史回放。群聊另外按成员读取游标注入新增公开消息（最近最多 50 条、24,000 字符）及当前触发消息；其他角色内容作为具名外部输入，私有工具记录不共享。输入快照、读取上界、游标与认领原子保存，执行失败时恢复游标。

重启后有效 queued 任务会继续处理，残留 running 标为 interrupted，不自动重放。正常退出中断当前运行；有失败或中断前序的协作会取消后续安排，其他有效排队任务可继续。流式片段在内存中展示，结束或停止时保存；强制退出可能丢失最后一次运行的未保存片段。停用角色时，在同一事务中更新启用状态并停止包含该角色待办的协作；取消已停止任务的模型上下文，重新启用不重放。停止与工具投递串行提交，晚到结果不能改写终态。

密钥保存在系统凭据存储，服务名为 `com.tongxi.app`，数据库只存随机引用。界面提交密钥后清空输入，读取配置不会返回已有密钥。更换服务地址必须重新填写密钥，避免把已有凭据意外发送给另一个服务。不要在测试请求中粘贴密钥。

新角色可复用默认连接的密钥引用；之后更换默认连接不会改动已有角色的地址、模型或密钥。更换角色密钥时只影响该角色；凭据只有在默认配置和所有角色都不再引用时才清理。

本地运行不等于离线推理。选择真实模型时，请求内容会发送到配置的服务；只有「本地检查」不访问模型网络。

## 工程与规划

- `internal/agent`：Eino Runner、OpenAI 兼容适配与本地固定测试模型。
- `internal/app`：角色与会话业务、单执行槽调度器、凭据管理及连接验证生命周期。
- `internal/store`：SQLite 迁移、角色、会话、消息、运行记录和 P0 验证记录。
- `frontend/src`：角色与会话界面、连接验证和模型设置。
- `frontend/wailsjs`：Wails 生成的绑定；修改绑定方法后通过 Wails 重新生成。
- `cmd/probe`：不依赖桌面窗口的链路验证命令。

长期架构、迭代需求、实施计划和参考来源见 [规划索引](plan/README.md)。实际进度与验收证据见 [第一期进度](plan/001-mvp-20260927/progress.md)。
